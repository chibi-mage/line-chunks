# Known limitations — 0.48.2-alpha.1

- Validated on Forge Neo commit `cb3c1fc535482003156e1c00ffe9802eeea92e97`, Gradio 4.40.0. Other hosts, themes and all browser/scroll combinations need validation.
- Main txt2img/img2img positive prompts only. Negative, ADetailer and other textboxes remain manual. The obsolete Advanced draft editor is removed.
- Classification is an incomplete reviewed vocabulary. Ruleset 0.1.32 contains 1318 exact rules (including 231 curated mappings) and 21 patterns. Unknown/random triggers can receive provisional L7 placement. Recognized worn accessories across the body, garment exposure and cutout states default to L4. Unreviewed phrases can still need context; vocabulary coverage is incomplete. Manual placement does not train rules.
- Structural headings and semantic suggestions differ. A colored template can still contain misplaced tags. Organize uses review and Apply; Auto Fix immediately applies eligible solo/configured Couple plans and reports blocked cases without partial changes.
- Auto Fix requires one explicit plain single-character count per editable owner. Configured Couple support is Basic only, with exact standalone `---`, readable first/last/none shared position, disabled Tile Mode and no active Common Prompts constructs. Advanced/Mask, custom/newline separators and ordinary confirmed-character blocks use reviewed Organize. Shared content and standalone regional BREAK boundaries stay locked. Unknown triggers may still use provisional L7. Eligibility is a text heuristic, not proof of ownership or generation quality.
- Newest is strong L1. Action is deliberately ambiguous L2/L7 and blocks automatic editing when unresolved inside an editable region; a locked shared occurrence stays unchanged.
- Regional organization needs standalone literal `---` rows and explicit shared position. Character blocks need confirmed ranges. Two to eight editable blocks are supported. Ordinary workflows require standalone BREAK; reviewed BREAK import also accepts row-leading BREAK before text on the same row. BREAK never establishes a character without explicit confirmation.
- Inline/custom controls, schedules, dynamic syntax, malformed groups, cross-line constructs or ambiguous ownership may block organization. Planner limits are 20,000 source characters and 200 editable items.
- Compact rendering uses real blank heading rows because a native textarea cannot independently reserve a visual heading above every logical line. These rows appear in copied prompts/metadata. Organization can change whitespace/order as previewed. The host textarea may normalize line endings.
- Labels, choices, bundles and snapshots are page-local. Explicit draft files preserve source and line labels, while pending choices/bundles and Undo snapshots are excluded. Reload/external replacements can clear unsaved state. Revert is an exact snapshot guard, not permanent undo history.
- Reordering can change generation results. Multi-character expression/appearance bleed depends on model conditioning. Forge Couple or inpainting may help; MDPF labels do not isolate conditioning or change generation settings.
- Authored automated regressions and selected live UI samples support this alpha. They are not independent accuracy or generation-quality evidence. Package extraction/removal validation is not a fresh running-Forge test.
- Blank starters support Solo, ordinary two-character placement lines and 2–8 Forge Couple characters. Blank-slot labels are page-local unless explicitly exported/reopened; source rows persist but empty headings can disappear after reload, edits across sections, Reset labels or external replacement. Enter, multiline paste and joins contained within one known template section retain its label/character; control boundaries do not inherit it. Count/placement defaults must be edited for the scene. Templates do not configure Forge Couple.
- ComfyUI support, global classification overrides and public distribution remain future work. Original extension code is MIT licensed; bulk external datasets and private reference fixtures are not part of the package.

- L3 ordering covers 304 reviewed exact descriptors and bounded full hair/eye/pupil forms. Unranked L3 tags, explicit labels and protected groups stop sorting. Generic marks use a general skin category; ears/horns/tails/wings use a final appendage group. This writing convention does not infer anatomy or conditioning, and may change generation results when explicitly applied.

- L4 uses 360 reviewed exact ordering descriptors and recognized qualified garment/accessory/location forms. States lead each unprotected run; generic details use an early unlocated group. Complete outfits use the torso group; recognized weapons/carried accessories use a final group after footwear. Equal areas stay stable, without layer inference or contradiction repair. Unranked/manual/weighted/bundled tags and ownership boundaries stop sorting.

- The 200 editable-item total remains in effect even with multiple owners. Eight detailed characters can exceed it; the whole proposal is rejected without a partial write. The combined 18-profile audit is authored development validation, not a representative real-world accuracy estimate.

- Selected-item corrections are prompt/session choices. Applied destinations use existing section line labels rather than persistent per-tag rules; reset labels to resume scoring. Selecting items never changes their region, splits a weighted group or edits a verified bundle. No saved global overrides are provided.

- Focus tags express camera/subject intent and do not establish counts, character ownership or guaranteed framing. L5 gaze-first ordering applies only within automatic plain runs; manual labels, weights, bundles and scope boundaries retain priority. Conflicting gazes/emotions are preserved, and expression bleed remains model-dependent.

- The hand/eye/face interaction corrections are reviewed exact phrases, not a full language parser. Unreviewed variants may still be unknown or need manual placement. Correctly recognized L2 tags inside a confirmed plain L3–L7 character range now block that range; keep camera/actions outside it.

- Bare reviewed weapons and umbrellas use the L4 carried-prop convention; explicit beach/patio/garden umbrellas, umbrella stands and weapon racks use L6. Other scene interpretations need manual placement. The extension does not infer holding, bind object attributes or add missing object descriptions. Furniture remains L6 even when its interaction is L2.

- The five user-pasted Civitai samples retain unknown trigger/LoRA associations and ambiguity. The later author background policy makes day/sunlight/water and other reviewed scene defaults firm L6. Adding a count still does not bypass unrelated ambiguity such as medieval/action. Bare flower/leaf terms and energy wings remain provisional rather than guessed.

- BREAK import is reviewed only: two to eight character blocks and at most four locked shared blocks. Character blocks must begin with one plain single-character count and organize L3–L7. Shared aggregate counts must agree; conflicting/mixed declarations and unsupported syntax require manual work. Embedded middle-row BREAK remains unsupported. Unknown clothing/trigger strings can retain provisional L7. Shared formatting is not converted to MDPF automatically, and this feature does not promise a complete colored multi-character display.

- Qualified outfit support is bounded to 48 reviewed nouns, a fixed modifier list and up to four modifiers for the new patterns. Existing broader garment rules are retained. Actions use complete supported verb-object phrases; arbitrary prose, new nouns and trigger strings can still need review. No tag synthesis or classifier training.

Add character is insertion-only, supports up to eight characters and leaves existing solo/aggregate counts untouched. Match Basic Couple standalone --- and shared position manually. BREAK/custom-separator/unclear-owner drafts use manual editing. Adding a character does not configure regional conditioning.

Save / load draft provides explicit JSON file persistence for source and labels only. No auto-save, browser storage, generation settings or cross-version migration is provided. Pending review choices and previous Undo snapshots are excluded. Saved Couple guidance does not configure conditioning.

The usability pass checked 360/560-pixel prompt columns in the local harness and selected workflows in running Forge. These are container-width checks, not full mobile-browser validation. Native resize styling remained available; a physical resize drag was not exercised by the browser automation. Live draft download/file selection were permission-blocked during this pass, so current live save/load verification remains pending; portable draft round-trip and controller guards passed automated tests.
